## Бизнес-правила
| №    | Правило                                                                                                                   |
|------|---------------------------------------------------------------------------------------------------------------------------|
| 1    | Если `board_type` не входит в `{"edge", "center", "inner"}`, функция выбрасывает `ValueError`.                            |
| 2    | Если `offset_mm` или `width_mm` равен `None`, результат - `"missing"`.                                                    |
| 3    | Если `offset_mm` или `width_mm` равен `NaN`, функция выбрасывает `ValueError`.                                            |
| 4    | Если `width_mm <= 0`, функция выбрасывает `ValueError`.                                                                   |
| 5    | Номинальная ширина доски: `edge` и `center` - 145 мм, `inner` - 100 мм.                                                   |
| 6    | При `strict=True` допуски умножаются на 0,5: смещение 5 - 2,5 мм, ширина 3 - 1,5 мм.                                      |
| 7    | Если \|`width_mm` − номинал\| > допуска ширины, результат - `"damaged"`. Это правило проверяется раньше правила смещения. |
| 8    | Если \|`offset_mm`\| <= допуска смещения, результат - `"ok"`.                                                             |
| 9    | Если допуск < \|`offset_mm`\| <= 2 * допуска, результат - `"shifted"` (доску можно исправить).                            |
| 10   | Если \|`offset_mm`\| > 2 * допуска, результат - `"rejected"`.                                                             |

## 6. Вывод
 
**Покрыты все ветви**


**Оставшиеся риски.** Стопроцентное покрытие ветвей не означает отсутствия ошибок.
 
1. **Типы данных не валидируются.**
2. **Точность float на границах.** Тесты проверяют только "круглые" границы.
3. **Порядок проверок.** Неизвестный `board_type` вызывает ошибку даже тогда, когда доска не найдена (`None`).
4. **Тесты проверяют правила, а не измерения.**

**Роль тестирования для качества ПО.**
- Модульные тесты формализуют бизнес-правила: таблица тест-кейсов одновременно служит проверяемой спецификацией допусков.
- Тесты фиксируют поведение на границах, где ошибки встречаются чаще всего: например, `<` вместо `<=` превратит допустимое смещение 5 мм в брак.
- Автотесты служат регрессионной защитой при изменении допусков или добавлении новых типов досок.
- В жизненном цикле ПО модульное тестирование — самый ранний и дешёвый этап поиска дефектов. Ошибка в допуске, найденная тестом, стоит минуты.
- Анализ остаточных рисков показывает границы метода: модульные тесты нужно дополнять интеграционным тестированием всего конвейера.

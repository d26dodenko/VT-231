
# Лабораторная работа №1
## Составление тест-кейсов для готового кода

### 1. Описание тестируемого программного модуля

Для выполнения лабораторной работы выбрана библиотека `email-validator` версии 2.3.0, написанная на языке Python.

Исходный код проекта:
https://github.com/JoshData/python-email-validator

Библиотека предназначена для проверки корректности адресов электронной почты. Она позволяет определить соответствие email-адреса установленным требованиям, выполнить нормализацию адреса и обнаружить ошибки в его структуре.

В качестве тестируемой функции используется `validate_email()`, которая принимает адрес электронной почты и дополнительные параметры проверки.

### 2. Бизнес-правила тестируемого модуля

На основании функциональности библиотеки выделены следующие правила:

1. Email-адрес должен содержать разделительный символ `@`.
2. Email-адрес должен содержать непустую локальную часть перед символом `@`.
3. Email-адрес должен содержать корректную доменную часть после символа `@`.
4. Локальная часть адреса может содержать латинские буквы, цифры и некоторые специальные символы.
5. Точки в локальной части адреса не должны следовать непосредственно друг за другом.
6. Пробелы в обычной незаключённой в кавычки локальной части адреса недопустимы.
7. Доменное имя не должно начинаться с дефиса.
8. При нормализации доменная часть адреса приводится к нижнему регистру.
9. При обнаружении некорректного email-адреса генерируется исключение `EmailNotValidError`.
10. При успешной проверке функция возвращает объект с информацией о проверенном и нормализованном адресе.
11. В строгом режиме (`strict=True`) дополнительно проверяется ограничение длины локальной части адреса в 64 октета.
12. Проверку возможности доставки почты на домен можно отключить параметром `check_deliverability=False`.


### 3. Анализ входных и выходных данных

#### 3.1. Входные параметры

Для тестирования используется функция `validate_email()` библиотеки `email-validator`.

Функция принимает следующие параметры:

email - адрес электронной почты, который необходимо проверить. Тип данных str.

check_deliverability - параметр типа bool, определяющий необходимость проверки возможности доставки почты на указанный домен.

strict - параметр типа bool, включающий строгую проверку длины локальной части email-адреса.

В большинстве тестов используется значение check_deliverability=False, позволяющее выполнять проверку синтаксиса адреса без обращения к DNS-серверам.

#### 3.2. Выходные данные

При успешном выполнении проверки функция возвращает объект ValidatedEmail, содержащий информацию о проверенном адресе.

Основные выходные данные:

normalized - нормализованный email-адрес.

local_part - локальная часть адреса, расположенная перед символом @.

domain - доменная часть адреса, расположенная после символа @.

Если переданный адрес не соответствует требованиям, функция генерирует исключение EmailNotValidError.

#### 3.3. Допустимые значения

К допустимым значениям относятся корректные email-адреса, содержащие локальную и доменную части, разделённые символом @.

Локальная часть может содержать латинские буквы, цифры, точки и некоторые специальные символы, например +.

Допускается использование букв верхнего регистра в доменном имени. При обработке адреса доменная часть нормализуется и приводится к нижнему регистру.

#### 3.4. Недопустимые значения

К недопустимым значениям относятся адреса без символа @, с отсутствующей локальной или доменной частью, пустые строки, адреса с несколькими символами @, последовательными точками в локальной части и недопустимыми пробелами.

Также некорректными считаются адреса с доменными метками, начинающимися с дефиса.

В строгом режиме дополнительно проверяется превышение допустимой длины локальной части адреса.

#### 3.5. Граничные значения

Одним из основных граничных условий является длина локальной части email-адреса.

При использовании strict=True максимальная длина локальной части составляет 64 октета.

Для адресов, состоящих из символов ASCII, проверяются следующие значения:

63 символа - допустимое значение.

64 символа - максимально допустимое значение.

65 символов - недопустимое значение, вызывающее исключение EmailNotValidError.

В автоматизированных тестах реализованы проверки длины 64 и 65 символов.

Дополнительно проверяются пустая локальная часть и отсутствие домена.

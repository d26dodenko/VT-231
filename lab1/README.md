## 1. Бизнес-правила

Для выполнения лабораторной работы используется модуль `power_supply.py`, предназначенный для расчёта энергопотребления компьютерных комплектующих и подбора блока питания.

Программа содержит три функции:

- `calculate_total_power()` — рассчитывает суммарное энергопотребление комплектующих.
- `recommend_psu()` — определяет рекомендуемую мощность блока питания.
- `check_power_supply()` — проверяет достаточность мощности выбранного блока питания.

При анализе программы были выделены следующие бизнес-правила:

| № | Правило |
|---|---|
| 1 | Если `cpu_power <= 0`, функция вызывает `ValueError`. |
| 2 | Если `gpu_power < 0`, функция вызывает `ValueError`. Нулевое значение допускается, поскольку компьютер может работать без дискретной видеокарты. |
| 3 | Если `other_power < 0`, функция вызывает `ValueError`. |
| 4 | Суммарное энергопотребление определяется как сумма потребления процессора, видеокарты и остальных компонентов. |
| 5 | Для подбора блока питания необходимая мощность рассчитывается с запасом 20% от суммарного потребления. |
| 6 | Подбор выполняется из номиналов `450, 550, 650, 750, 850, 1000` Вт. |
| 7 | Функция `recommend_psu()` возвращает минимальный номинал из списка, который не меньше рассчитанной необходимой мощности. |
| 8 | Если ни один номинал не подходит, функция вызывает `ValueError`. |
| 9 | Если `psu_power <= 0`, функция проверки выбранного блока питания вызывает `ValueError`. |
| 10 | Если мощность выбранного блока питания больше или равна необходимой, функция `check_power_supply()` возвращает `True`, иначе `False`. |

### Расчёт необходимой мощности

Суммарное энергопотребление компьютера определяется по формуле:

`Ptotal = Pcpu + Pgpu + Pother`

Необходимая мощность блока питания с учётом запаса:

`Prequired = Ptotal * 1.2`

Например, для конфигурации с потреблением процессора 181 Вт, видеокарты 360 Вт и остальных компонентов 60 Вт:

`Ptotal = 181 + 360 + 60 = 601 Вт`

`Prequired = 601 * 1.2 = 721.2 Вт`

Из заданного списка номиналов минимальным подходящим является блок питания мощностью 750 Вт.

Таким образом, модуль позволяет рассчитать потребление компьютера, подобрать рекомендуемый номинал БП или проверить достаточность мощности уже выбранного блока питания.

## 2. Анализ входных и выходных данных

### Входные параметры

| Параметр | Тип | Допустимые значения | Недопустимые значения |
|---|---|---|---|
| `cpu_power` | `int` или `float` | Число больше 0 | `<= 0` |
| `gpu_power` | `int` или `float` | Число больше или равно 0 | `< 0` |
| `other_power` | `int` или `float` | Число больше или равно 0 | `< 0` |
| `psu_power` | `int` или `float` | Число больше 0 | `<= 0` |

Параметры задаются в ваттах (Вт).

Параметр `psu_power` используется только функцией `check_power_supply()`.

При этом программа рассчитана на числовые значения. Отдельная проверка типов входных данных в модуле не реализована.

### Выходные параметры

| Функция | Выходное значение |
|---|---|
| `calculate_total_power()` | Суммарное энергопотребление компонентов в ваттах либо `ValueError` |
| `recommend_psu()` | Рекомендуемый номинал БП из списка `450, 550, 650, 750, 850, 1000` либо `ValueError` |
| `check_power_supply()` | `True`, `False` либо исключение `ValueError` |

### Классы эквивалентности

| Класс | Условие | Результат |
|---|---|---|
| 1 | Все значения потребления компонентов допустимы | Возвращается их сумма |
| 2 | `cpu_power <= 0` | `ValueError` |
| 3 | `gpu_power < 0` или `other_power < 0` | `ValueError` |
| 4 | Необходимая мощность не превышает 450 Вт | Рекомендуется БП 450 Вт |
| 5 | Необходимая мощность находится между соседними номиналами | Выбирается следующий подходящий номинал |
| 6 | Необходимая мощность превышает 1000 Вт | `ValueError` |
| 7 | `psu_power >= Prequired` | `True` |
| 8 | `0 < psu_power < Prequired` | `False` |
| 9 | `psu_power <= 0` | `ValueError` |

### Граничные значения

| Параметр или условие | Граничные значения | Ожидаемый результат |
|---|---|---|
| `cpu_power` | 0 / -10 | `ValueError` |
| `gpu_power` | 0 / -50 | Допустимое значение / `ValueError` |
| `other_power` | 0 / -10 | Допустимое значение / `ValueError` |
| `psu_power` | 0 / -1 | `ValueError` |
| Необходимая мощность около 450 Вт | 450 / 451,2 | Рекомендация 450 / 550 Вт |
| Необходимая мощность около 750 Вт | 750 / 751,2 | Рекомендация 750 / 850 Вт |
| Проверка БП при необходимых 600 Вт | 599 / 600 / 650 | `False` / `True` / `True` |
| Проверка БП при необходимых 120 Вт | 119 / 120 | `False` / `True` |
| Необходимая мощность выше 1000 Вт | 1080 | `ValueError` |

Граничные значения позволяют проверить правильность работы операторов сравнения, используемых в условиях программы.

Особое внимание уделяется ситуациям, когда рассчитанная мощность точно совпадает с номиналом блока питания или незначительно превышает его.

**Оставшиеся риски.**

Несмотря на успешное выполнение всех тестов, полное покрытие не гарантирует отсутствия ошибок.

1. **Проверка типов данных.** В программе отсутствует отдельная валидация строковых и других неподходящих типов входных параметров.

2. **Особенности чисел с плавающей точкой.** При использовании дробных значений вблизи границ возможны особенности вычислений типа `float`.

3. **Ограниченный список блоков питания.** Программа рассматривает только заранее заданные номиналы. Другие мощности, существующие на рынке, не учитываются при подборе.

4. **Упрощённая модель энергопотребления.** Расчёт не учитывает кратковременные скачки мощности, эффективность блока питания и другие характеристики реального оборудования.

**Роль тестирования в обеспечении качества ПО.**

- Модульное тестирование позволяет убедиться, что отдельные функции выполняют предусмотренные бизнес-правила.
- Проверка граничных значений помогает обнаруживать ошибки в условиях сравнения. Например, замена `>=` на `>` может привести к неправильному результату при точном совпадении мощности.
- Автоматизированные тесты позволяют быстро проверять работоспособность программы после изменения исходного кода.
- Тестирование является важной частью жизненного цикла программного обеспечения, поскольку способствует раннему обнаружению дефектов.
- Анализ оставшихся рисков позволяет определить, какие дополнительные проверки потребуются при дальнейшем развитии программы.
